  ~1800 YAML de `docs/conocimiento/`, y el problema crecía una migración por cada subida

  Suite completa local: **704 tests, OK (skipped=1)**.

  `static/img/nodos/**` (push de solo contenido no dispara la suite) + `test --parallel auto`
  (el bug de pickle es solo Windows local). El job `test` de CI bajó a **~3 min**.
- **Railway (dashboard):** los loaders (`import_knowledge_tree`, `load_node_content`,
  `load_exercise_bank`, `publish_knowledge_nodes`) estaban en el *Custom Start Command*,
  corriendo síncronos antes de abrir el puerto (el patrón que causó el 502 de julio). Se
  movieron al *Pre-Deploy Command* — fase aparte que no bloquea gunicorn. El *Custom Start

  sobre archivos de config, igual que con el start command). Se borró para no dejar config
  muerta. La regla de config de deploy vive en `CLAUDE.md`.
- **Regla nueva en `CLAUDE.md`:** subir contenido = YAML + SVG + push, **sin migración**.
